## Опции

| Опция | Значение |
|---|---|
| `TARGET ...` | `host`, `host:port`, `[ipv6]:port` или `https://host[:port]/path` (путь, query и fragment игнорируются) |
| `-f`, `--targets-file FILE` | цели из файла, по одной на строку, `#` начинает комментарий |
| `--port PORT` | порт TLS для всех целей (по умолчанию 443) |
| `--sni NAME` | отправить NAME в SNI и сверять сертификат с этим именем (удобно для IP) |
| `--ssh`, `--ssh-port N` | дополнительно прочитать баннер SSH (порт 22 или N) |
| `--no-tls` | пропустить TLS, например только SSH |
| `--ca-file FILE` | проверять цепочку по CA из FILE вместо системного хранилища |
| `--no-trust-check` | не проверять цепочку |
| `--timeout СЕК` | таймаут каждой пробы, по умолчанию 5 |
| `--concurrency N` | параллельных рукопожатий на цель, по умолчанию 6 |
| `--warn-days N` | сертификат, которому осталось меньше N дней, это `MEDIUM` (по умолчанию 14) |
| `--fail-on УРОВЕНЬ` | с какого уровня код возврата 1: `LOW`, `MEDIUM` (по умолчанию), `HIGH`, `CRITICAL` или `never` |
| `--ignore ПРАВИЛО` | принять известный риск: правило показывается как *ignored* и не учитывается |
| `--list-rules` | показать все ID правил и выйти |
| `--json`, `--out FILE`, `--sarif FILE` | JSON на экран (без баннера), JSON в файл, SARIF 2.1.0 в файл |
| `--no-color` | без цвета (также `NO_COLOR`; `FORCE_COLOR=1` включает цвет принудительно) |
| `--no-banner` | не печатать ASCII-баннер |

## Как идёт проверка

Для каждой цели vetls:

1. один раз разрешает имя и выбирает первый адрес, принимающий TCP-подключение; все пробы идут на этот адрес, так
   что DNS round-robin не смешивает результаты разных бэкендов (если адресов несколько, это будет в отчёте);
2. пробует рукопожатие с каждой версией протокола (от SSLv3 до TLS 1.3);
3. пробует рукопожатие ровно с одним слабым шифром, для 17 наборов, на TLS 1.2 и ниже;
4. проверяет цепочку сертификатов отдельным рукопожатием по системному хранилищу или `--ca-file`;
5. анализирует сертификат (срок, ключ, подпись, SAN, срок жизни) и выставляет уровни.

Это около 23 коротких TCP-подключений на цель, по умолчанию по 6 одновременно.

## Коды возврата

| Код | Значение |
|---|---|
| `0` | нет находок уровня `--fail-on` и выше, все проверки прошли |
| `1` | есть находка уровня `--fail-on` (по умолчанию `MEDIUM`) или выше, даже если другая проверка не удалась |
| `2` | проверка не удалась (хост недоступен, на порту нет TLS) или неверные аргументы |
| `130` | прервано |

Неудачная проверка не скрывает находку: если TLS недоступен, а SSH показывает протокол 1.5, итог `HIGH`, код 1.
`overall_severity` равен `ERROR` только когда не удалась ни одна из запрошенных проверок.

## Уровни серьёзности и правила

Итоговый уровень равен максимуму среди сработавших правил; каждое правило выводится со стабильным ID
(`vetls --list-rules`).

| Уровень | Правила |
|---|---|
| `CRITICAL` | `TLS-SSLV3`, `CIPHER-EXPORT`, `CIPHER-ANON`, `CERT-EXPIRED` |
| `HIGH` | `CIPHER-RC4`, `CIPHER-NULL`, `CIPHER-DES`, `CERT-NAME-MISMATCH`, `CERT-NOT-YET-VALID`, `CERT-WEAK-SIGNATURE` с MD5, `SSH-PROTO-1` |
| `MEDIUM` | `TLS-TLS10`, `TLS-TLS11`, `TLS-NO-MODERN`, `CIPHER-3DES`, `CERT-UNTRUSTED`, `CERT-SELF-SIGNED`, `CERT-EXPIRES-SOON`, `CERT-WEAK-KEY`, `CERT-WEAK-SIGNATURE` с SHA-1, `CERT-NO-SAN`, `CERT-SAN-EMPTY`, `CERT-SAN-ERROR`, `CERT-UNKNOWN-SIGNATURE`, `CERT-ANALYSIS-FAILED`, `SSH-PROTO-1-99` |
| `LOW` | `TLS-NO-TLS13`, `CIPHER-CBC`, `CIPHER-NO-PFS`, `CERT-LONG-LIFETIME` |
| `INFO` | ничего не найдено |

**Срок сертификата** сверяется с графиком CA/B Forum (ballot SC-081) по дате выпуска: 398 дней с сентября 2020,
200 дней с 15 марта 2026, 100 дней с 15 марта 2027, 47 дней с 15 марта 2029.

**Доверие.** Самоподписанный сертификат указывается один раз (`CERT-SELF-SIGNED`, без дубля «недоверенный»);
просроченный указывается как просроченный. Самоподписанный сертификат, который вы явно передали через `--ca-file`, не
помечается.

Отсутствие находок не доказывает безопасность. То, что проверить не удалось, выводится строками `[?]` и на уровень не
влияет.

## Форматы вывода

**JSON** (`--json`, `--out`): для одной цели один отчёт с ключами `tool`, `version`, `target`, `scanned_at`,
`environment`, `overall_severity`, `errors`, `tls`, `ssh`. Для нескольких целей: обёртка с массивом `reports`.
Каждая находка: `{"id", "severity", "message"}`. Пример есть в [английской версии](usage.md#output-formats).

**SARIF 2.1.0** (`--sarif`) для панелей code scanning: по результату на находку, уровни `error` (CRITICAL/HIGH),
`warning` (MEDIUM), `note` (LOW), с `security-severity` и стабильными отпечатками.

## В CI

```yaml
- run: pipx install vetls
- run: vetls -f deploy/endpoints.txt --sarif vetls.sarif --out vetls.json --ignore CIPHER-CBC
- uses: github/codeql-action/upload-sarif@v3
  if: always()
  with:
    sarif_file: vetls.sarif
```

## Как библиотека

```python
from vetls import TLSScanner, score

findings = TLSScanner("example.com", timeout=5, sni=None, ca_file=None).scan_sync()
result = score(findings, warn_days=21, ignore=["CIPHER-CBC"])
print(result["severity"], [i["id"] for i in result["issues"]])
```

## Ограничения

- Возможности проверки ограничены **локальным OpenSSL**: SSLv3, RC4, DES и export-шифры во многих системах
  выключены при сборке и помечаются как «не проверяется здесь».
- Шифронаборы TLS 1.3 не перечисляются (модуль `ssl` не позволяет их выбирать).
- Размер DH-параметров не измеряется (Logjam не обнаруживается); нет проверки отзыва (OCSP/CRL) и Certificate
  Transparency.
- Перебор шифров эвристический, возможны ложноотрицательные результаты на нестандартных серверах.
- Список публичных суффиксов встроенный и неполный.
- SSH проверяется только по баннеру, без KEX/host key/MAC и без сопоставления версий с CVE.
